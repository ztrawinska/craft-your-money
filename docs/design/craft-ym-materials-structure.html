Materials Library
reuse without retyping

A supporting screen with one promise: enter a material once, use it in every product. The library is optional by design — everything here can also happen ad-hoc inside a product. Stock and low-stock alerts are the second, equally optional layer. No AI on this screen; the alert strip is deterministic.

Library rules (from PRD)

  • Required to save: name, unit cost, unit type. Optional: stock quantity, low-stock threshold — the entire stock layer can be ignored forever.
  • No stock quantity → no stock logic. The row shows no stock cell, no alert ever fires, the material still works everywhere for costing.
  • Alerts fire only when both threshold and stock are set and stock falls below threshold. Amber, consistent with the dashboard's low-stock attention rows.
  • Ad-hoc materials can be promoted to the library — but from the product detail side ("Save to library" after entry), not from this screen. This screen only manages what's already saved.
  • Deleting a library material never touches existing products. Product rows store their own copy of name and cost; the reference simply detaches. The delete confirmation says exactly this.

Deliberately omitted for MVP

  • Search — libraries under ~40 items scan fine; revisit when real libraries outgrow scrolling.
  • Usage counts ("used in 3 products") — useful, but post-MVP; it adds a query per row for a nice-to-know.
  • Categories or grouping — a flat alphabetical list is the honest MVP.

Desktop rules

  • Inline cell editing, per PRD: numeric cells (cost, stock, threshold) edit in place on click — dashed underline is the affordance. Name edits via row click → the same inline form as mobile. Unit type changes via the form only, since changing a unit invalidates the cost.
  • "Not tracked" and "not set" are ghost text, not empty cells — the optional layer stays legible as a choice, and clicking a ghost cell starts tracking.
  • Alphabetical sort by name is default; headers sort on click. The low-stock row keeps its amber stripe regardless of sort position.
  • Delete remains inside the edit form on both layouts — no hover-revealed row actions, per the acceptance criteria.
